## 1. 背景与动机

### 问题
ClaudeDataBackup 当前是 GUI 优先的工具。CLI 模式（`main.py`）虽然存在，但输出是给人看的 print 文本，退出码不规范，没有能力自描述。这意味着：
- Claude Code 或其他本地 Agent 无法可靠地调用它（不知道它能干什么、不知道结果是成功还是失败）
- 用户必须手动打开 GUI 才能操作

### 目标体验
用户装完 DMG → 拖到 Applications → 对 Claude Code 说"我装了个备份工具，你去看下你怎么用" → Agent 自动：
1. 读取工具的能力描述
2. 发现本机有哪些 Claude 内容可备份
3. 执行备份
4. 把结果展示给用户

**全程不需要打开 GUI**。万一崩了，用户双击打开 GUI app，也能看到 Agent 驱动的备份记录（因为共享 `manifest.json`）。

### 朋友的完整需求

1. **基础功能与备份说明**
   - (a) 明确工具的使用方法，以及在备份时可以指定哪些参数
   - (b) 提供 CLI 模式的对应说明并呈现给 agent
   - (c) 让 agent 了解，在同一个路径下多次备份是可以实现增量备份的

2. **信息交互与呈现**
   - (a) 在一定程度上将信息交还给 agent，由 agent 呈现给用户
   - (b) 比如可以展开查看电脑上的 Claude Code 有哪些内容
   - (c) 支持用户通过语言对话的方式与 agent 交互，根据用户描述的内容来选择备份对象、路径及方式

3. **结果查看**
   - 备份完成后，可以生成一个 index.html 文件，方便用户以交互体验更友好的方式进行打开和查看

4. **无感体验**
   - 用户视角：下载 dmg → 拖进 Applications → 告诉 Claude Code → 全自动
   - GUI 可见：Agent 驱动的备份在 GUI 里也能看到（共享 manifest）

### 3.2 `--json` 全局 flag

- 加到现有 argparse：`ap.add_argument("--json", action="store_true")`
- 当 `--json` 激活时：
  - logger 函数改为收集到 list，不 print
  - 子命令直接输出 JSON
  - 备份命令完成后输出 `{"status": "ok", "stats": stats, "log": messages}`
  - 进度信息保留在 `"log"` 数组中，Agent 可以忽略也可以展示

### 3.3 标准化退出码

| Code | 常量 | 含义 | Agent 应对 |
|------|------|------|-----------|
| 0 | `EXIT_SUCCESS` | 成功 | 完成 |
| 1 | `EXIT_ERROR` | 运行时错误 | 检查 stderr，重试或报告 |
| 2 | `EXIT_INVALID_ARGS` | 参数无效 | 修正命令 |
| 3 | `EXIT_AUTH_FAILURE` | 认证失败 | 提示用户登录 Claude Desktop |
| 4 | `EXIT_PARTIAL` | 部分成功 | 检查 JSON 中哪些 mode 失败 |

检测逻辑：
- stats 中 `mode_a.status == "skipped"` 且 reason 包含 "no_key" → auth failure
- 仅 mode_a 被选中且 auth failure → exit 3
- mode_a 失败但 mode_c 成功 → exit 4（partial）
- 全部成功 → exit 0

### 3.4 `AGENTS.md`

Agent 自描述文档，放在项目根目录。内容包括：
- 工具简介（三个模式）
- Quick Start（4 步 workflow）
- 子命令 + JSON schema
- 全局 flags
- 退出码表 + Agent 应对策略
- 示例 bash 命令
- 文件路径速查

这个文件的设计意图是：Agent 读了它就能完整理解工具并开始工作，不需要猜。

### 3.5 `ClaudeDataBackupCLI.spec`

Console-only PyInstaller spec：
- 入口：`main.py`
- `console=True`（关键差异：有标准输出）
- `excludes`：customtkinter、tkinter、AppKit、gui、scheduler、daemon
- `datas`：locales + AGENTS.md
- 无 BUNDLE（不打 .app，纯 CLI 二进制目录）

同时更新现有 `ClaudeDataBackup.spec` 的 datas 加入 AGENTS.md。

### 3.6 i18n

`zh.json` 和 `en.json` 各新增约 20 个 key：
- `cli.json_help`、`cli.subcommand_*`
- `agent.capabilities_title`、`agent.list_title`、`agent.status_title`
- `agent.mode_a_cookie_ok/none`、`agent.mode_b_cache_ok/none`、`agent.mode_c_sessions/none`
- `agent.manifest_none/found`、`agent.last_backup`、`agent.no_backups_yet`
- `exit.success/error/invalid_args/auth_failure/partial`

## 4. 设计意图与决策

### 为什么用 pre-scan 而不是 argparse subparsers？

现有 CLI 是扁平的 flag 结构（`--incremental --mode a --output /path`）。如果用 `add_subparsers()`，要么把现有命令包进 `backup` 子命令（破坏兼容），要么在顶层 parser 和子 parser 之间做复杂的 fallback（容易出 bug）。

pre-scan `sys.argv[1]` 是最安全的方案：如果第一个参数是已知子命令就路由过去，否则走原来的 argparse 流程。和 `--schedule` 的处理方式一致。

### 为什么 `--json` 不改 logger 函数本身？

`run()` 和 `run_incremental()` 内部大量使用 `logger(msg)` 打印进度。如果要让这些函数输出 JSON，最干净的方式是：
1. 把 logger 替换为一个收集器（append to list）
2. 函数照常调用 logger，完全不感知 JSON 模式
3. 函数返回 stats dict
4. 在最外层把 stats + messages list 序列化为 JSON

这样 `run()`、`run_incremental()`、`run_mode_a()` 等函数零改动。

### 为什么 AGENTS.md 是静态文件而不是 `capabilities` 子命令的输出？

两个都做，但用途不同：
- `capabilities --json`：机器读的，精确 schema，Agent 程序化解析
- `AGENTS.md`：Agent 的 LLM 读的，自然语言 + 示例，提供"理解"层面的上下文

Agent 的典型流程是：先读 AGENTS.md 建立认知 → 用 `capabilities --json` 获取精确参数 → 用 `list --json` 发现内容 → 执行备份。

### 为什么不做 `--select` 参数让用户选择备份哪些项目？

朋友的需求 (2c) 是"支持用户通过语言对话的方式与 agent 交互，根据用户描述的内容来选择备份对象"。这个选择逻辑应该在 Agent 侧完成，不在工具侧。Agent 通过 `list --json` 看到所有项目，然后根据用户描述决定传什么 `--mode` 和 `--set-backup-dir` 参数。

如果后续需要项目级别的选择（比如只备份某个 Claude Code project），可以在 config 里扩展 `claude_code_projects` 的 `_selected` 机制，通过新的 CLI flag 暴露。但 v0.4.0 先不做，保持简单。

### 退出码 3 vs 4 的区分逻辑

- **exit 3（auth failure）**：用户只选了 mode_a，且没有 sessionKey → Agent 可以精确告诉用户"请先登录 Claude Desktop"
- **exit 4（partial）**：mode_a 失败但 mode_c 成功 → Agent 告诉用户"在线备份失败（需要登录），但本地会话已备份成功"

这个区分对 Agent 的对话质量很重要——模糊的"出错了"远不如"具体哪个环节出了什么问题"有用。

## 7. 验证方式

```bash
# 1. 子命令 JSON 输出（验证 JSON 合法性）
claude-data-backup capabilities --json | python -m json.tool
claude-data-backup list --json | python -m json.tool
claude-data-backup status --json | python -m json.tool

# 2. 子命令人类可读输出
claude-data-backup capabilities
claude-data-backup list
claude-data-backup status

# 3. 增量备份 JSON 模式
claude-data-backup --incremental --mode c --json | python -m json.tool
echo $?  # 应为 0

# 4. 向后兼容
claude-data-backup --incremental --mode c  # 无 --json，行为不变
claude-data-backup --version               # 不变

# 5. 退出码
claude-data-backup --incremental --mode a --json; echo $?  # 3 如果无 sessionKey

# 6. 人类可读 + 子命令
claude-data-backup list  # 应输出格式化的状态文本，不是 JSON
```
